# SquadSpot

A group outing planner for the web. Choose a city, a group budget, how long you have, when you start and what you enjoy; SquadSpot builds three alternative day plans from real places, shows each one on a map, and opens the route in Google Maps.

Built with React Native for Web (Expo) on the frontend and Python/FastAPI on the backend, with place data from OpenStreetMap stored in Supabase (PostgreSQL). The same codebase also runs as an iOS/Android app.

## Features

- **Accounts:** sign up, sign in, password reset with a 6-digit email code, profile editing, sign out. Sessions survive a page refresh.
- **Planner:** search any active city (Vadodara is the default), or use the browser's location to pick the nearest one; total group budget split per person; group size; duration (1–12 h); start time (06:00–23:00); interests: Nature, Food, Adventure, Chill, Shopping, Culture, Movies.
- **Three alternative plans** per request, each with arrival–departure times, a category per stop and the expected expense per person. Places without a listed price show an estimated range (e.g. "Est. ₹150–250"); places slightly over budget are tagged.
- **Interactive route map** (Leaflet + OpenStreetMap) with numbered stops, and one-click navigation in Google Maps.
- **Warnings** when a plan runs longer than the chosen duration.
- **Web-native behaviour:** every screen has its own URL (`/plan`, `/trip`, …), browser Back/Forward work, the current trip survives a refresh, messages appear as in-app notifications, and the layout adapts from phone to desktop width.

## Web technologies used

| Concept | Where it is used |
|---|---|
| HTML & CSS (generated by React Native for Web) | All screens; extra CSS for focus rings in `frontend/src/utils/webStyles.js` |
| Responsive design | Two-column planner and wider trip cards at ≥ 900 px (`useWindowDimensions`) |
| Client-side routing / History API | One URL per screen with Back/Forward support (`frontend/src/navigation/AppNavigator.js`) |
| REST API with `fetch` and JSON | `frontend/src/services/api.js` ↔ FastAPI routes in `backend/app/api/` |
| Authentication with JWT Bearer tokens | Supabase Auth; verified by the backend on every protected request |
| Web Storage | `localStorage` for the session and planner draft, `sessionStorage` for the current trip |
| Geolocation API | "Use my location" in the planner |
| Third-party map library | Leaflet with OpenStreetMap tiles (`frontend/src/components/RouteMap.web.js`) |
| CORS | Backend allows the local frontend origins (`backend/app/main.py`) |
| Form validation | Frontend checks for instant feedback, repeated on the backend with Pydantic |
| Accessibility | Labels and roles on icon-only buttons, visible keyboard focus |

## How a plan is made

1. **Normalise** (`backend/app/data_layer/normalizer.py`): load the city's active places, keep those matching the chosen interests and mood, drop places costing more than 20 % over the per-person budget, give unknown prices an estimated range from known prices in that city (`cost_estimates.py`), and drop near-duplicate entries.
2. **Greedy filter** (`greedy_filter/filter.py`): keep the 50 most promising places, making sure every chosen interest is represented.
3. **Genetic algorithm** (`ga_engine/ga_core.py`): evolve routes for 100 generations, scoring each with `scoring_engine/fitness.py` (interest coverage, rating, mood match and use of the available time, minus travel, waiting, budget and time penalties). The three best routes that visit clearly different places are kept.
4. **Schedule** (`scheduler/schedule.py`): compute arrival and departure times from the chosen start time, respecting opening hours and a 1 a.m. latest finish.

## Running locally (Windows PowerShell)

Requirements: Python 3.11+ and Node.js 20+, plus the Supabase project credentials from the team.

**Backend** (terminal 1):

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
Copy-Item .env.example .env        # then fill in the three SUPABASE_ values
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Check it at http://127.0.0.1:8000/api/health (API docs: http://127.0.0.1:8000/docs).

**Frontend** (terminal 2):

```powershell
cd frontend
npm install
Copy-Item .env.example .env        # EXPO_PUBLIC_API_URL=http://127.0.0.1:8000
npx expo start --web --port 3000
```

Open http://localhost:3000. Use port 3000 (or 8081): these are the origins the backend allows.

Keep `.env` files out of Git; the Supabase service-role key must never reach the frontend.

## API

| Method | Endpoint | Auth | Purpose |
|---|---|---|---|
| POST | `/api/auth/signup` | – | Create an account |
| POST | `/api/auth/login` | – | Sign in with email and password |
| POST | `/api/auth/oauth` | – | Sign in with a Google/Apple ID token |
| POST | `/api/auth/refresh` | – | Exchange a refresh token for a new session |
| POST | `/api/auth/logout` | Bearer | Revoke the session |
| GET / PATCH | `/api/auth/me` | Bearer | Read / update the profile |
| POST | `/api/auth/reset-password` | – | Email a recovery code |
| POST | `/api/auth/verify-otp` | – | Set a new password with the code |
| GET | `/api/cities?search=&limit=` | – | Active cities (search by name) |
| POST | `/api/itinerary` | Bearer | Generate up to three plans |
| GET | `/api/pois` | – | Diagnostic list of places |
| GET | `/api/health` | – | Health check |

`POST /api/itinerary` body: `budget` (per person), `total_time_minutes`, `preferences` (e.g. `["food","culture"]`), `mood` (`"chill"` or null), `city` (e.g. `"Vadodara, Gujarat"`), optional `start_time` (`"HH:MM"`), optional `use_my_location` with `latitude`/`longitude`. The response holds the best plan at the top level and all plans in `options`.

## Known limitations

- Place coverage and categories come from OpenStreetMap and vary by city; most places have no listed price, so estimates are shown and labelled as such.
- Travel time is a straight-line estimate (2 min per km), not live traffic.
- Google sign-in on web needs `http://localhost:3000` registered on the project's Google OAuth client; Apple sign-in works only in the iOS app.
- On web the session token is kept in `localStorage`, which is fine for this project but would move to secure cookies for a public deployment.
- `/api/pois` returns at most 1,000 rows (Supabase's default page size).

## Mobile app

The same code runs on iOS/Android with `npx expo start`. Web-only parts are marked in the code with a comment on how to bring them to mobile: the map (`RouteMap.js` → `react-native-maps`), "Use my location" (`expo-location`), and the focus-ring CSS (not needed on mobile).
